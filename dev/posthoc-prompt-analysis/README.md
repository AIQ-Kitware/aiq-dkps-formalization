# Post-hoc prompt analysis

A study of how much human steering the "auto"-formalization actually required,
and what kinds of agent mistakes had to be corrected. Built from the Claude Code
session transcripts, which are pruned at roughly 30 days — the snapshot in
`local/` exists because the oldest surviving formalization session was already
at that edge.

Designed to be run independently by every agent that worked on this project, on
its own machine, and merged into one joint analysis.

## Layout

```
tools/                    the pipeline (committed, shared, do not fork per-agent)
findings/<agent-id>/      each machine's results (committed, disjoint, mergeable)
local/                    raw snapshot + bulky derived files (GITIGNORED, never commit)
AGENT-PROMPT.md           hand this to another agent to replicate on its machine
```

`findings/<agent-id>/` holds `prompts.jsonl`, `events.jsonl`, `metrics.json`,
`taxonomy.tsv`, `manifest.json`, generated `ANALYSIS.md` + `index.md`, and the
hand-written `FINDINGS.md` + `MISTAKES.md`. About 1.3M per agent.

`local/` holds `raw-all/` (verbatim `~/.claude/projects/`), `claude-meta/`
(`history.jsonl`, settings), `sessions/*.md` (readable per-session prompt +
response transcripts) and `mistake-evidence.md`.

## Read these

| file | what it is |
|---|---|
| `findings/*/FINDINGS.md` | **Start here.** Where the friction was. |
| `findings/*/MISTAKES.md` | Classification of agent mistakes, classes A–E, with cited instances. |
| `findings/*/ANALYSIS.md` | Generated metrics. Regenerated by `analyze.py`; do not edit. |
| `JOINT-ANALYSIS.md` | Combined view once more than one agent has reported. |
| `local/sessions/*.md` | Each human prompt with the agent's immediate response. |

## Run it

```bash
export POSTHOC_AGENT_ID=<hostname>-<who>     # e.g. toothbrush-jon
export POSTHOC_NOTE="non-default --scope, missing sources, tool changes"  # optional
python3 tools/extract_prompts.py             # raw-all/ -> findings/$POSTHOC_AGENT_ID/
python3 tools/analyze.py                     # -> ANALYSIS.md, metrics.json, taxonomy.tsv
python3 tools/mistakes.py                    # -> local/mistake-evidence.md
python3 tools/merge_findings.py              # -> JOINT-ANALYSIS.md (after collecting agents)
```

Widen the scope beyond this repo with `--all-projects` or `--scope <substring>`.

**Check the session list the extractor kept, do not trust the count it prints.**
Scope is matched on session `cwd`, and `cwd` is a poor proxy for project
membership. Both non-default checkouts so far needed a correction: on
`aivm-2404-edward` the formalization is a subdirectory of a parent repo, so
sessions open at the parent (fixed by scoping per session rather than per
record); on `aiq-gpu-edward` the agent works out of `$HOME`, so only 4 of 8
in-project sessions matched, and those 4 matched by accident. Record any
non-default `--scope` in `$POSTHOC_NOTE`.

## Scope

Extraction is filtered to the `aiq-dkps-formalization` tree and its TauCeti
subrepos (`DEFAULT_SCOPE` in `tools/extract_prompts.py`). No session was ever run
with a TauCeti subrepo as its cwd — all subrepo work was driven from the parent
repo — so the filter only excludes unrelated projects.

## How a human prompt is identified

Transcripts store many things as `type: "user"` records that no human typed.
A record is kept only if:

- `isSidechain` is false — sub-agent Task prompts are stored as user records too,
  and are agent-authored;
- `message.content` is text, not a `tool_result`;
- `origin` is absent or `origin.kind == "human"` — excludes task notifications,
  coordinator messages and hook injections on versions carrying the field;
- the text does not begin with a known harness marker (`[Request interrupted`,
  `Stop hook feedback:`, `<local-command-stdout>`, compact continuations, …).

Records are deduped by `uuid`: resuming or forking a session copies every prior
record into the new file, which inflates raw counts about 3x (1,280 → 389 rows
for this repo before dedup).

Validated against `local/claude-meta/history.jsonl` (which independently logs
typed CLI prompts) and by manual sampling of every residual bucket. Synthetic
turns are not discarded — they go to `events.jsonl`, because interrupts,
Stop-hook replays and compactions are friction signals in their own right.

### Prompts typed while the agent was running

Typing into the box mid-run does **not** create a `user` record. It creates
`type == "queue-operation"` records: `enqueue` when typed, then `dequeue` if the
turn is eventually delivered (a normal user record then appears) or `remove` if
the queue is flushed by ESC, a queue edit, or a compaction. A removed one never
becomes a user record, so a `user`-only scan loses it even though the human typed
it and `history.jsonl` logged it. This undercounts every store in proportion to
how often the human typed while the agent was busy — on `aiq-gpu-edward` that was
119 of 355 typed prompts (34%), and one session held 201 enqueues against 44
dequeues.

They are emitted to `events.jsonl` as `event: "queued_prompt_dropped"`, **not** to
`prompts.jsonl`, so prompt counts stay comparable with findings produced before
this was added; a prompt typed and then dropped is friction, like an interrupt.
An agent that has not re-run extraction since will report 0 of them, which is a
missing measurement rather than a zero.
