\label{app:accounting}

\subsection{Study universe and snapshot semantics}

Program-wide token totals additionally include measured work from explicitly
allowlisted repositories; at this snapshot the allowlist contains the primary
repository and cross-repository Tau Ceti foundations work.  The Git history is
pinned at \AccountingSnapshot{}.  Manuscript-only commits are excluded from the

\subsection{Observation classes}

Exact commit-level instrumentation was introduced on \InstrumentationSnapshot{}.
There are \CommitsBeforeInstrumentation{} included primary-repository commits
before that point.  Backfilled harness transcripts recover some earlier usage;
other earlier work has no equivalent telemetry.

We retain three evidence classes:
\begin{enumerate}
  \item \textbf{Exact commit-attributed measurement.}  A ledger row names a Git
        commit in the included primary history.  There are
        \ExactMeasuredCommitCount{} such commits at the current snapshot.
  \item \textbf{Measured but commit-unattributed usage.}  A retained
        \texttt{pending@...} ledger segment contains measured tokens but lacks a
        defensible one-to-one commit assignment.  There are
        \PendingSegmentCount{} such measured segments, containing
        \PendingTurns{} model turns.  Timestamp overlap is retained only as an
        allocation candidate, with allocation left unresolved.
  \item \textbf{Unmeasured work.}  This includes unrecovered pre-instrumentation
        work and work performed through interfaces, including chat interfaces,
        for which equivalent local harness telemetry is unavailable.
\end{enumerate}

\subsection{Model-resolved accounting and pricing}

Every token-bearing ledger row contains a per-model token vector.  The analysis
verifies that the model-level ordinary-input, cache-write, cache-read, and output
counts sum exactly to the row-level totals.  Consequently a session that changes
model attribution follows the measured per-model vectors associated with the
work.  Measured usage is first resolved by model and token class; monetary cost
is a separate transformation.

Historical prices are stored as explicit, dated inputs.  A model contributes
to the dollar estimate only when the required token-class rates for its
applicable interval are available.

\subsection{Revisable valuation of measured usage}

The valuation layer consumes the measured model-resolved token vectors and a
versioned assumptions file.  Public API prices carry provider, effective date,
token class, and source URL.  Cache-write duration is absent from the ledger, so
the central calculation uses the five-minute cache-write rate and reports an
all-one-hour-cache sensitivity.

Operational energy and carbon use a versioned serving-stack scenario
\citep{crall2026llmresource} with throughput, server power, per-turn overhead,
cache factors, PUE, and grid carbon intensity.  Low, central, and high settings
provide sensitivity scenarios.  A simpler per-token model provides an
order-of-magnitude cross-check.  The operational boundary excludes model
training, embodied hardware, client devices, network energy, and other lifecycle
effects.
