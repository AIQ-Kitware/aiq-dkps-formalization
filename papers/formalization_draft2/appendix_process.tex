\section{Detailed resource-accounting methodology}
\label{app:accounting}

\subsection{Study universe and snapshot semantics}

The resource study uses a deliberately explicit study universe rather than
identifying ``the project'' with one Git repository.  Commit-level coverage is
computed from the primary formalization repository.  Program-wide measured token
usage additionally includes ledger rows from the explicitly allowlisted
repositories in \texttt{analysis\_config.json}; at the current snapshot these
include the primary repository and cross-repository work that the authors identify
as part of the Tau Ceti foundations contribution.  This distinction matters
because the ledger can observe useful formalization work performed outside the
Git history available in the present checkout.

The Git history is pinned at \AccountingSnapshot{}.  The full commit identifier is
retained in generated source metadata and exposed as a PDF tooltip on the date,
but is not used as a presentation value.  The pinned primary-repository history
contains \RepositoryHistoryCommitCount{} commits before study exclusions and
\HistoryCommitCount{} after them.  A configurable path rule excludes a commit
only when \emph{all} of its touched paths lie under
\path{papers/formalization_draft2/}; mixed commits remain in scope.  At this
snapshot the rule excludes \ExcludedPaperOnlyCommitCount{} commits.  The purpose
is prospective as well as retrospective: advancing the analysis snapshot during
paper preparation should not silently charge manuscript production to the
formalization whose cost is being studied.

\subsection{Observation classes}

Exact commit-level instrumentation was introduced on \InstrumentationSnapshot{}.
There are \CommitsBeforeInstrumentation{} included primary-repository commits
before that instrumentation point.  Backfilled harness transcripts recover some
usage from the earlier period, but they do not make the historical record
complete.

We retain three evidence classes rather than collapsing them into one estimated
project total:
\begin{enumerate}
  \item \textbf{Exact commit-attributed measurement.}  A ledger row names a Git
        commit in the included primary history.  There are
        \ExactMeasuredCommitCount{} such commits at the current snapshot.
  \item \textbf{Measured but commit-unattributed usage.}  A retained
        \texttt{pending@...} ledger segment contains measured tokens but lacks a
        defensible one-to-one commit assignment.  There are
        \PendingSegmentCount{} such measured segments, containing
        \PendingTurns{} model turns.  Timestamp overlap is retained only as an
        allocation candidate; it is not treated as an allocation.
  \item \textbf{Unmeasured work.}  This includes unrecovered pre-instrumentation
        work and work performed through interfaces, including chat interfaces,
        for which equivalent local harness telemetry was not retained.
\end{enumerate}

\subsection{Measured lower bound and token classes}

The primary empirical quantity is the measured lower bound, not an extrapolated
``total cost.''  At \AccountingSnapshot{} the allowlisted program ledger records
\LedgerTurns{} model turns and \LedgerOutputTokens{} output tokens.  Its
\LedgerBillableInputTokens{} billable-input accounting measure aggregates
ordinary input, cache-write, and cache-read quantities according to the local
ledger schema.  For reproducibility we preserve the primitive token classes as

The committed lifetime rollup is treated as a cache rather than an authority:

inheriting a stale aggregate.

\subsection{Model-resolved accounting and pricing}

Every token-bearing ledger row contains a per-model token vector.  The analysis
verifies that the model-level ordinary-input, cache-write, cache-read, and output
counts sum exactly to the row-level totals.  Consequently a session that changes
models need not be assigned wholesale to whichever model happened to make the
commit.  Measured usage is first resolved by model and token class; monetary cost
is a separate transformation.

Historical prices are therefore stored as explicit, dated inputs in
\path{data/model_pricing.csv}.  The scripts emit no dollar figure for a model
unless all required token-class rates for the applicable interval are supplied.
This avoids the especially misleading practice of multiplying a heterogeneous
multi-model token total by one average token price.

\subsection{Exploratory reconstruction of unmeasured usage}

The missingness mechanisms are not exchangeable.  Pre-instrumentation work,
unretained chat-interface work, harness failures, and genuinely manual commits
have different observation processes.  The current script therefore treats
extrapolation as exploratory.  It fits a regularized model only to exactly
measured primary-repository commits, validates temporally using rolling-origin
splits, and emits predictions only for commits with positive LLM provenance that
are neither exactly measured nor overlapped by a measured pending segment.
Model identity is retained as a stratum/predictor when evidence supports it, and
outputs explicitly record how many directly measured commits calibrate each
resolved model label.

Any final quantitative result based on extrapolation should present at least:
(i) the measured lower bound; (ii) measured pending usage without forced
commit-level allocation; and (iii) a modeled range with validation and
sensitivity analyses.  The third quantity must not replace the first two.

\section{Git and ledger model provenance}
\label{app:model-provenance}

Git \texttt{Co-authored-by} trailers and exact ledger rows answer related but
nonidentical questions.  A trailer records contribution provenance chosen at
commit time; a ledger row records models actually observed by an instrumented
harness.  The analysis therefore stores the raw trailer string, a canonicalized
trailer label, any study-specific historical interpretation, and exact ledger
models separately before deriving a resolved provenance label.

\subsection{A bounded GPT-5.6 chat-interface rule}

For this study only, the first author identified a historical convention in the
Git trailers: on unledgered commits dated from June 3 through August 14, 2026,
GPT-5.6 ``High'' and ``Thinking'' were chat-interface setting labels for the
GPT-5.6 Sol model.  The analysis therefore maps those two raw labels to
GPT-5.6 Sol and marks the interaction channel as chat interface \emph{only} when
there is no exact ledger model attribution.  The rule matches
\BoundedGPTChatRuleCommitCount{} commits at the pinned snapshot.  The date bound
is part of the rule so that this project-specific historical knowledge cannot be
silently projected onto future naming conventions.

Raw trailer labels remain in the generated manifest.  If an exact ledger row is
present, it is authoritative for measured model use regardless of the trailer.
Raw GPT-5.6 Sol trailers are not automatically classified as chat-interface work;
they remain review candidates unless contemporaneous evidence or an author
annotation establishes the channel.

\subsection{Why Anthropic trailer disagreements are not normalized away}

The authors observed a different failure mode for Anthropic model trailers:
within a long-running harness session the active model could be changed without
also changing the commit-time co-author instruction.  A Fable-attributed commit
can therefore contain work performed partly by Opus, or conversely.  Because the
ledger's per-model vector directly observes measured use, the analysis does not
rewrite Anthropic trailer labels to force agreement.  Instead, partial or
disjoint trailer/ledger model sets are retained in
\path{model_provenance_disagreements.csv} as provenance-review signals.

This distinction also guards against an incorrect inference in the other
direction: a Git trailer can corroborate LLM involvement in an unmeasured commit
without establishing a token count or proving which interface generated the
work.

The logs also distinguish ordinary submitted prompts from explicit interrupts
and from typed steering that was removed before becoming an ordinary model turn.
This matters methodologically: counting only transcript ``user messages'' can
miss some of the most interventionist human behavior.  Final reporting should
state exactly which event classes survive in each interface and avoid comparing
raw counts across interfaces as though capture were uniform.

\subsection{Coordination tooling and the YWS source census}

The paper-keyed YWS source census illustrates why process provenance can require
more than retrospective recollection.  In later discussion the first author did
not initially remember whether he had explicitly asked for formalization
tracking.  A contemporaneous commit record showed that he had requested a
manifest and programmatic coverage check.  The resulting implementation then
went substantially beyond a simple checklist: it keyed obligations on the paper,
separated mathematical status from build-backed verification, detected missing
and private declarations, and added generated/checked workflow machinery.  The
human subsequently refined the tooling, constrained its scope, and incorporated
it into progress review.

The point is not to assign a binary ``human'' or ``agent'' origin to the census.
Rather, the record shows an iterative division of initiative: a human request,
agent elaboration into coordination infrastructure, and later human adoption and
constraint.  This is precisely the sort of development history that becomes
difficult to reconstruct from memory after many short-lived operational
interactions.

\subsection{Interaction archaeology and incomplete recollection}

For this project, retained traces sometimes function as \emph{interaction
archaeology}: they allow later reconstruction of what was requested, what was
elaborated by an LLM, and how an artifact entered the working process.  We treat
contemporaneous records as stronger provenance evidence than later recollection
when they conflict.  Author recollection remains useful evidence, especially for
unlogged chat interactions, but should be labeled as such.

This observation is deliberately narrow.  A single long-running project does
not establish a general cognitive claim about memory.  It does establish a
practical reproducibility limitation: missing chat logs remove not only token
telemetry but also evidence about initiative, correction, and decision history.

\section{Process-study limitations and possible cuts}
\label{app:process-limitations}

The detailed process analysis is intentionally broader than the material likely
to survive in the main paper.  Before submission we expect to retain only
results that change the interpretation of the mathematical contribution or make
resource claims reproducible.  Candidate appendix-only or removable material
includes fine-grained prompt taxonomies, individual model-provenance mismatch
cases, detailed imputation diagnostics, and the interaction-archaeology case
study.  The generated artifacts remain useful even if the corresponding prose is
cut: they provide an auditable evidence base for any quantitative statements
that remain.
