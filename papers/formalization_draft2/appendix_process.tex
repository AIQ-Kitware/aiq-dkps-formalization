\section{Formalization process}
\label{app:formalization-process}

The formalization was developed in Lean~4 with Mathlib
\citep{demoura2021lean4,mathlib2020}.  The AI-facing tools were the ChatGPT chat interface, Claude Code, and Codex.
We did not use a separate formalization-agent framework.  The repository itself
was compiled with the ordinary Lean and Lake toolchain.

The formalization used the following recurring cycle.
\begin{enumerate}
  \item We supplied the source paper to an LLM and asked it to transcribe the
        mathematical statements and decompose the proof into intermediate
        obligations.
  \item Before building missing theory, we searched Mathlib, other Lean
        developments, and the mathematical literature for existing definitions,
        lemmas, or formalizations that could be reused or adapted.
  \item The LLM implemented definitions and intermediate lemmas, filled theorem
        proofs, compiled the result, and revised failed proofs using compiler
        feedback.  Larger arguments were commonly organized into written proof
        roadmaps before implementation.
  \item We repeatedly compared each Lean theorem with the source statement,
        including hypotheses, endpoint conventions, ambient dimension, norm
        class, and operator domain.  These checks were performed both by humans
        and by additional LLM reviews.  A narrower or otherwise mismatched
        statement was revised and checked again.
\end{enumerate}

As the development grew, we also asked the LLMs to build repository scripts that
enumerated source claims and linked them to Lean declarations.  Those tools were
introduced after substantial formalization had already been completed and were
used to check coverage and to revisit earlier statements systematically.  The
resulting source-coverage evidence is summarized in
Appendix~\ref{app:source-coverage}.

\section{Source coverage and formalization evidence}
\label{app:source-coverage}

For Davis--Kahan, the denominator used in the paper is
\FormalizationDKResultCount{} results: the four unnumbered Section~2 theorems and
every named theorem, proposition, lemma, and corollary established in the paper.
Definitions, examples, open questions, proof steps, and results attributed to
other sources are excluded.  Twenty-eight counted results are proved at the
scope stated in the source.  Proposition~4.4 remains in the denominator and is
formally refuted as printed, with a repaired result proved separately.

For YWS, the source audit contains \YWSCensusEntryCount{} entries spanning the
three theorem-level claims and the lemmas, equations, identities, examples,
conventions, and corrections used to verify them.  Of these,
\YWSCensusExplicitAdditionCount{} are explicitly marked additions beyond the
printed paper, and all \YWSCensusVerifiedCount{} entries resolve to declarations
in the default build.

\subsection{Model-resolved tokens, pricing, and energy}

Each token-bearing row records ordinary input, cache writes, cache reads, and
output by model.  Historical API prices are applied after token accounting.
Using the dated public price inputs gives an API-equivalent list-price value of
\MeasuredApiEquivalentCost{} for the observed lower-bound usage; valuing every
recorded Anthropic cache write at the one-hour rate gives
\MeasuredApiEquivalentCostOneHour{}.

The energy calculation uses a versioned serving model with throughput, server
power, cache-work factors, per-turn overhead, and datacenter power usage
effectiveness \citep{crall2026llmresource}.  The operational boundary covers LLM
serving and excludes model training, embodied hardware, client devices, and
network energy.  The paper reports both the central serving-model value and a
separate per-token cross-check.

\subsection{Coverage proxies and project-scale extrapolation}

Exact telemetry covers \ExactMeasuredCommitCount{} of \HistoryCommitCount{}
primary-repository commits (\ExactMeasuredCommitShare{}).  Those commits account
for \ExactMeasuredLeanLineChurn{} of \TotalLeanLineChurn{} cumulative Lean-line
insertions and deletions (\ExactMeasuredLeanLineChurnShare{}).  This raw Git
quantity is the directly measured text-volume proxy.  We also report an adjusted
proxy that removes \LeanLineChurnAdjustmentTotal{} known non-LLM line changes
from bulk repository operations.  The adjusted denominator is
\AdjustedTotalLeanLineChurn{} Lean-line changes, of which
\AdjustedExactMeasuredLeanLineChurn{} have exact telemetry, giving
\AdjustedExactMeasuredLeanLineChurnShare{} coverage.

The project-scale estimates in \cref{tab:resource-extrapolation} use the linear

gives \AdjustedLeanChurnScaledOperationalEnergy{}.  The model assumes comparable
token intensity between observed and unobserved work under the selected
denominator.
