\label{app:source-coverage}

The main text summarizes mathematical coverage without reproducing the
bookkeeping used to establish it.  For Davis--Kahan, the counted result set is
fixed at \FormalizationDKResultCount{}: the four unnumbered Section~2 theorems
and every named theorem, proposition, lemma, and corollary that the paper
establishes.  Definitions, proof steps, examples, open questions, and externally
attributed results remain source-audit material outside that denominator.  Of
the counted results, 28 are proved at the scope stated in the source and
Proposition~4.4 is formally refuted as printed and accompanied by a repair.

are created from the published document.  At the analysis snapshot it contains
\YWSCensusEntryCount{} entries spanning theorem-level claims, lemmas, equations,
identities, examples, conventions, and audit material, with
\YWSCensusExplicitAdditionCount{} explicitly labeled additions beyond the
printed paper.  All \YWSCensusVerifiedCount{} entries resolve to declarations in
the default build.  Status fields record exact matches, generalizations or
specializations, and compiled corrections.

\label{app:accounting}

\subsection{Study universe and snapshot semantics}

Commit-level coverage is computed from the primary formalization repository.
Program-wide token totals additionally include measured work from explicitly
allowlisted repositories; at this snapshot the allowlist contains the primary
repository and cross-repository Tau Ceti foundations work.  The Git history is
pinned at \AccountingSnapshot{}.  Manuscript-only commits are excluded from the
formalization-history corpus.

\subsection{Observation classes}

Exact commit-level instrumentation was introduced on \InstrumentationSnapshot{}.
There are \CommitsBeforeInstrumentation{} included primary-repository commits
before that point.  Backfilled harness transcripts recover some earlier usage;
other earlier work has no equivalent telemetry.

We retain three evidence classes:
\begin{enumerate}
  \item \textbf{Exact commit-attributed measurement.}  A ledger row names a Git
        commit in the included primary history.  There are
        \ExactMeasuredCommitCount{} such commits at the current snapshot.
  \item \textbf{Measured but commit-unattributed usage.}  A retained
        \texttt{pending@...} ledger segment contains measured tokens but lacks a
        defensible one-to-one commit assignment.  There are
        \PendingSegmentCount{} such measured segments, containing
        \PendingTurns{} model turns.  Timestamp overlap is retained only as an
        allocation candidate, with allocation left unresolved.
  \item \textbf{Unmeasured work.}  This includes unrecovered pre-instrumentation
        work and work performed through interfaces, including chat interfaces,
        for which equivalent local harness telemetry is unavailable.
\end{enumerate}

cache writes, cache reads, and output.  The analysis verifies that these vectors
sum to the row-level totals.  Historical API prices are stored as dated inputs
and applied after token accounting.

\subsection{Coverage proxies and project-scale extrapolation}

Exact telemetry covers \ExactMeasuredCommitCount{} of \HistoryCommitCount{}
included primary-repository commits (\ExactMeasuredCommitShare{}).  Those commits
also account for \ExactMeasuredLeanLineChurn{} of \TotalLeanLineChurn{} cumulative
Lean-line insertions and deletions (\ExactMeasuredLeanLineChurnShare{}).

The extrapolations in \cref{tab:resource-extrapolation} divide the exact
primary-repository token subset by each coverage fraction.  The first gives equal
weight to commits; the second uses changed Lean lines as a coarse text-volume
proxy.  Both assume comparable token intensity between observed and unobserved
portions under the selected denominator.
